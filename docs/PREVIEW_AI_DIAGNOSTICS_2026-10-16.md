# 預覽、AI 降階與選用標記影片：本輪紀錄

日期：2026-10-16。這是 **r100 建置後的 repository 修改**，尚未建置成下一版、尚未安裝正式 Host。

## 版本與驗收邊界

- 本輪瀏覽器讀到 Aaron 正式 Dashboard 頁尾仍為 r99；使用中來源為 026c02、subtype=2、1920×1080 HEVC 20 FPS。不能把另一台 C701 筆電的回報當成這台電腦的現況。
- r100 是前一輪已建置並驗證的候選包，不包含這份文件所列的新增修改。沒有自動安裝、UAC、修改攝影機登入、變更來源或重啟正式 Host。
- 原碼 MSE 已通過真實既有來源回歸：本輪播放時間約 82 秒，videoWidth=1920、videoHeight=1080、readyState=4，顯示約 20.3 FPS；上游活動 producer=1，測試時 consumer=2，關閉後回到 1。
- C701 的 3840×2160、MX250 長時間負載、另一台電腦、iPhone／電視相容性皆未由本輪重新驗收。

## 1. 日誌與預覽快取

原程式將 V0.2 的所有 warnings（包含正常活動採樣略過）改印成同一句泛稱警告。現在依固定白名單分類為採樣、來源重置、主要推論、裁切保存、通知排程或未分類；同類每 60 秒彙整次數。不輸出任意例外文字、攝影機 URL 或服務秘密。

正常略過影格現在明確帶 analysis_skipped；不再把它當成已分析的無貓影格、灌高完成 FPS 或清掉上一筆有效疊圖。

預覽快取修正：

- Windows HTTP JPEG 讀取使用 FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE，避免自己的讀者擋住原子替換。
- 先前遺留暫存檔清理失敗不再阻擋新影格寫入。
- 寫入失敗日誌列出失敗操作、系統碼、連續失敗張數；恢復時另有一條恢復通知。
- WinError 5 不能單獨證明是 ACL、防毒或讀檔占用；本輪並未更動權限或防毒設定。
- Windows 併行讀取／100 次替換測試通過；緊密零延遲替換曾遇暫時 WinError 5，保留有上限重試，不能宣稱共享讀旗標消除所有外部鎖定。

## 2–5. 畫質與 AI 降階

三條不同用途不可混為一談：

| 用途 | 目前限制／語意 | 效能影響 |
| --- | --- | --- |
| 攝影機／事件錄影／MSE 原碼 | 沿用已選 subtype；可為 4K20 | 原碼轉發主要在觀看端解碼，顯示成小視窗不會變成 1080p 解碼 |
| 共用 JPEG 影格 | 寬度上限最高 1920，是目前軟體政策，不是硬體或攝影機極限 | JPEG 編解碼、記憶體與網路用量增加 |
| 身分裁切 | V0.2 共用影格的寬度需求，最高 1280；不是每隻貓的裁切寬度 | 保留裁切細節；不足不補出真實像素 |
| YOLO | 長邊 640／960／1280／1920；實際會 letterbox 成模型輸入 | 大尺寸增加 CPU／GPU 推論成本；不等於影片再轉碼 |

共享 ingest 寬度取預覽、AI 與 V0.2 身分需求的最大值，再各自消費。不要求三項相同；單一解碼不等於後續縮放／JPEG／推論都免費。1920 寬只在橫向 16:9 時等於 1080p；直向畫面不能用相同名稱冒充高度。

MX250 的低溫低用量仍可能降階，因為原策略也看端到端分析耗時，且不自動恢復：

- 5 FPS 每張預算 200 ms；若解碼、程序傳輸、模型、追蹤及後處理持續超過預算，GPU 即使只有 15% 仍可能降階。
- 本輪改以最近最多 30 次真正分析的平均耗時判斷，至少 5 次才啟用；略過影格不稀釋耗時。wrapper 自己的感測器輪詢不再算入分析耗時。
- 降階快照保留觸發種類、當時負載／溫度／平均耗時／每張預算；UI 顯示端到端平均與目前預算，不把它稱為純 GPU 時間。
- 使用者可明確按「依已保存的分析上限重新嘗試 AI」恢復設定上限；重試不再永遠固定在 640／1 FPS。記憶體與高溫檢查仍在，持續超載仍降階。
- 本輪沒有取得 C701 筆電的歷史觸發樣本，因此不能認定它先前一定是耗時觸發；新欄位才提供可驗證的區分。

## 6. 瀏覽器 AI 疊圖

首頁與即時頁共用 HUD，新增「偵測框／身分候選／動作候選」三個開關；沿用既有預覽狀態請求，不新增 AI 模型、攝影機 producer 或影片轉碼。

- 基本 YOLO 回傳原圖正規化框；V0.2 回傳追蹤框與實驗性候選。不同貓分別顯示。
- 使用 DOM 疊加、textContent、防止無效／越界座標、依實際媒體 contain 區域放置。
- 只保留最近 2 秒採樣，停止、休眠、來源切換與隱藏分頁時清除。不宣稱與 20 FPS 影片逐幀同步。
- 合成雙貓瀏覽器驗收：獨立開關可操作、休眠後框數 0、圖片 src 移除；真實身分正確率不在本輪驗收範圍。

## 7. 選用標記匯出

事件人工回報內新增折疊的「匯出含 AI 標記影片」：

- 只讀已授權本機事件 MP4；需登入與 CSRF，同時只執行一份選用匯出，低於 2 GB 可用記憶體時拒絕。
- 限 60 秒影片，獨立短期 CPU 工作程序，1 個 CPU 執行緒，每秒抽取一次 YOLO 偵測；框僅顯示 0.5 秒，避免假裝整秒都是準確追蹤。
- 不以現時身分／行為冒充舊影片的標記，第一版只匯出貓框。舊事件缺少完整逐幀軌跡，必須明確重新分析，而不是把事件截圖的框畫滿整片。
- 在既有 H.264 相容轉碼中加入 drawbox，只有一次輸出編碼；有離線採樣解碼成本。保留原片與完整影片時間，不改平時 Telegram 流程、不自動發送 Telegram。
- 可選比較無框／帶框轉碼時間，額外一次比較轉碼必須勾選。頁面回報分析與編碼時間；未發送 Telegram 時 notification_ms=null，不能捏造通知耗時。
- 實際 Dashboard 合成 5 秒影片下載成功：分析 3390 ms、帶框流程 172 ms、無框 141 ms。素材沒有真貓，因此這不是有貓畫框成本或 MX250 基準。
- 另以已知座標的真實 FFmpeg 測試確認框僅在指定時間窗可見、H.264 相容、2 秒時長保留、原檔逐位元不變。

## 8. 休眠／節能／流暢與尚未完成

既有三模式保留：首頁預設節能 JPEG、即時頁預設 MSE 流暢、休眠停止此頁媒體與預覽請求。HUD 改到左上角並使用眼睛斜線圖示；流暢模式顯示 videoWidth × videoHeight 的真實解碼尺寸。

**尚未實作／未驗收，不能宣稱整體完成：**

- WebRTC 播放與經驗證的媒體權限路徑。
- HEVC 不相容時「共用、有人觀看才啟動」的硬體 H.264 轉碼。現階段仍直接降級 JPEG，並顯示原因。
- 新版的 C701 4K、MX250 長時間負載／掉幀／延遲、不同手機與電視。
- 真實 Telegram 帶框／無框通知耗時 A/B；本輪未向使用者發送額外影片。
- 新版建置、使用者安裝後的正式驗收。
