# CPU／RAM／磁碟長期資源趨勢

## 使用方式與定義

Dashboard「資源趨勢與行為統計」提供 1 小時、24 小時、7 天、30 天、90 天折線。
Host 啟動後獨立背景執行緒每 60 秒採樣，不需登入或保持瀏覽器開啟。
不重新啟動攝影機、不增加 ingest、不逐影格寫入資料庫。網頁僅進入頁面或操作查詢時讀取。

- 整台電腦 CPU 與 RAM：psutil 系統讀值。
- 守護者 CPU：相關程序 CPU time 差值除以時間及邏輯核心數，以整機容量 100% 為基準。
- 守護者 RAM：Host、Host 子程序（含 AI）、同應用根目錄的 Tray／go2rtc／FFmpeg／FFprobe RSS 總和。
  不收集其他軟體用量；RSS 共享頁可能重複計入，並非精確的 private working set。
- 磁碟：應用根目錄與實際 SQLite 所在 Data 目錄的檔案邏輯大小。Data 不重複算入 App；
  排除 App 根下 dist、.git、reports，跳過 symlink／junction，不代表整顆磁碟用量或 NTFS 配置大小。
  正式安裝計入 runtime、vendor、模型、程式，以及影片、快取、資料庫與寵物資料。

## 儲存及隔離

Data 下 `resource-history.db`，獨立 SQLite schema version 2；可重跑 migration 保留舊資料，WAL、busy timeout 500 ms。
固定欄位白名單，只有時間與數值；沒有帳號、來源 URL、命令列或任何秘密。
每次採樣清理 90 天前紀錄；正常每分鐘約 129600 筆上限。查詢最多約 601 個平均分段。
磁碟掃描獨立單一背景工作，每 15 分鐘一次；讀值附原始磁碟採樣時間，失敗保留最近值。
資源歷史失敗或 SQLite 鎖定只跳過該次記錄，不中斷影音。正常結束會發出停止訊號並有界等待。
服務停機與未量到的值為空白，不補 0；圖表不跨長中斷連線。長期間顯示平均而非瞬間峰值。

## 交付界線

repository 實作後需新發布包與使用者升級，正式 Host 才會開始累積歷史；不會自動恢復先前未保存的歷史。
不自動安裝或重啟正式 Host。90 天真實歷史、SYSTEM 長期採樣成本與 MX250 負載仍需部署後驗證。

## r88 Telegram 系統狀態

Telegram `/status` 或「📊 系統狀態」沿用既有授權及背景傳送佇列，顯示電腦名稱、CPU 型號、邏輯核心數、RAM GiB、GPU 型號。
硬體名稱以本機唯讀 registry／平台 API 查詢；不傳送帳號、來源或憑證。
每 60 秒記錄整機 CPU／RAM、可辨識的 NVIDIA GPU 用量與溫度、可用 CPU 溫度感測器、整機磁碟累積讀寫計數。
近一小時平均與峰值直接取原始紀錄，不使用折線圖分段平均取峰值；峰值是採樣峰值，不代表取樣間的瞬間峰值。
最近採樣超過 120 秒不冒充目前讀值。顯示筆數及涵蓋分鐘數；不足一小時不假稱完整一小時。
磁碟讀寫量使用區間相鄰累積計數差，重開機計數歸零的間隔不相減；缺測時為未提供，不推估停機期間。
Windows CPU 溫度與 Intel GPU 利用率可能無可用 provider，顯示未提供，不會自動安裝感測器驅動或捏造 0。
多 NVIDIA GPU 不任意把其中一張視為整體，暫標未提供；基本硬體清單仍列出已安裝顯示卡。
本輪本機生成狀態及單元測試可驗證接線；正式安裝、真實 Telegram 收到訊息與一小時實拍資料需使用者升級後再驗證。
