# 人工回報播放、導覽與身分學習接線

## 本輪修改（尚未建置／安裝）

- 人工回報播放器明確重新載入選定事件，顯示播放錯誤；使用受登入保護的 `video?playback=true`。
- H.264／yuv420p／相容索引影片直接播放；不相容影片透過既有組片器產生 H.264/AAC 相容副本。保留原片及原始下載功能，不重新拉攝影機。
- 每個 Host 同時只允許一段回報相容影片準備；轉碼限時 30 秒。副本只在臨時目錄，HTTP 回應結束後刪除。
- 共享導覽依指定對話中可讀取的三組順序保留：守護日常（總覽、即時畫面、事件與回報、趨勢分析）；管理 · 設定（來源與攝影機、寵物檔案、通知設定）；系統 · 維護（AI 與錄影、連線與安全、維護中心、日誌、進階設定）。加入本機 SVG 圖示，不用文字符號冒充圖示。
- 首次 `/setup` 已有帳號、來源、Telegram，以及可選身分／遠端教學；新增可重看的登入保護 `/help`，入口位於右上「更多操作 → 使用教學」。不重建帳號、不重設設定。

參考對話的 assistant 訊息在讀取工具中只回傳 content reference，無法核對其完整建議文字；導覽順序依該對話可讀取的使用者正式清單，不宣稱讀到了不可見的回答。

## 實機身分增量學習：目前程式事實

1. 「寵物檔案」登錄名稱、參考照片並建立 DINOv2 特徵；特徵必須非零。
2. 「AI 與錄影」選 V0.2 追蹤與規則行為（實驗性），確認實際 Host 使用此模式，而非基本找貓。
3. 對 **逐軌跡影像對照** 選擇已登錄個體／其他貓／不是貓。明確同意此裁切用於身分學習後才可排入特徵擴充；Telegram 與 Dashboard 均保存同意及撤回紀錄。必須有同軌跡裁切，不以整段多貓影片的名字猜測裁切對象。
4. V0.2 背景排程約每 30 秒檢查；身分工作繁忙時延後。每輪最多建立一份新特徵，不阻塞影音。
5. 裁切須至少 96px、清晰度通過門檻、模型版本一致、標籤無衝突；相似度 ≥0.995 的重複樣本排除。每隻最多保留 100 個回饋特徵。
6. SQLite 保存裁切證據、回報及狀態；寵物資料目錄的 `feedback_embeddings.npz` 保存合格增量特徵，原始 `embeddings.npz` 不被覆寫。
7. 身分分類器每次讀取參考及回饋特徵，依相似度與第一／第二候選差距判斷；不夠明確保存 unknown。這是擴充特徵庫，不是重新訓練 YOLO，也不是 Codex 人工推斷。

**限制：** 整段影片人工標籤仍不自動成為學習樣本。Dashboard 新增明確 media event→track→裁切修正入口，只有同意且品質合格才納入特徵；本機裁切不依賴 Telegram 啟用。沒有固定回報份數能保證成功；準確率仍須家庭實拍驗收。此輪未核對使用者另一台 C701 Host 的模式、樣本數或最新特徵時間。

## 驗證邊界

相關 Web／回報／學習單元測試與合成 HEVC→H.264 API 整合測試，不等於正式事件在使用者瀏覽器播放成功。正式 Host 未重啟、未升級；真實回報影片與手機／桌面逐頁視覺驗收仍待後續部署。
