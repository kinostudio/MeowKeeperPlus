# 受控回饋學習（experimental）

## 狀態與範圍

2026-10-10：r72 安裝 manifest 已確認包含此實作；家庭辨識準確率與正式背景回饋學習仍未驗收。
這是擴充身分參考特徵庫，不是重新訓練 YOLO／DINOv2，也不會自動提高信心分數。
只有 V0.2 逐軌跡管線會執行；基本 YOLO 模式仍只找貓。

## 資料流程

1. 已選擇參與回饋的收件人收到逐軌跡摘要時，保存對應 cat track 的裁切 JPEG。
2. 使用者明確確認該軌跡「是貓咪」與寵物身分；原有 receipt、白名單、更新去重及歷史紀錄不變。
3. 共用現有身分 embedder 與 LOW 優先佇列，預設每 30 秒檢查，最多計算 1 個新特徵。
4. 通過品質、同模型版本及去重檢查後，原子發布獨立 `feedback_embeddings.npz`。
5. 現有 IdentityClassifier 讀取原登錄特徵加上回饋特徵；原本 unknown／分數／名次差距規則不變。

「兩隻都在」屬於整個事件的場景回報，沒有逐軌跡對應時不得用來學習任何個體。
不從舊通知的整張畫面猜測裁切；新增功能前沒有保存的軌跡裁切無法追溯學習。

## 品質與撤回

- 只接受同 track、事件時間範圍內影像，裁切不得與另一隻已偵測貓的框重疊。
- 最小邊長 96、模糊度門檻 25、單張最多 256 KiB；未偵測到的物件仍可能混入，需人工檢查。
- 多位回報者身分衝突、任一回報「不是貓咪」、未確認、模型版本不符，不採用。
- 保留期 30 天、最多 512 張證據、每隻最多 100 個回饋特徵；設定集中於 `FeedbackLearningPolicy`，pipeline 可注入覆寫。
- 下一輪背景檢查撤除否定／衝突／過期樣本；不是立即同步撤回，需等待下一輪與佇列排程。
- 不覆蓋 `embeddings.npz`、參考照片或登錄特徵數；獨立回饋檔損壞會被忽略，不停止找貓。
- 只擴充已啟用、具有同版本手動參考特徵的寵物；不自動建立新寵物。

SQLite schema 13 新增 `identity_feedback_evidence`，保存裁切 hash、JPEG、拍攝時間、特徵及處理狀態。
schema 14 為兩輪回饋歷史新增獨立 `motion` 欄位：行走／奔跑保存為 `other_active` 加 walking／running，不歸類為玩耍。
屬私人資料，不進 Git／發布包；完整資料備份須包含 SQLite 與 pets 目錄。
證據刪除不抹除不可覆寫的回報歷史。SQLite 刪除資料不等於檔案立刻縮小；需沿用容量維護。

## 行為回報

行為仍是區域與時序規則候選。人工行為回報僅比較「模型候選 vs 人工標籤」，不自動改區域、規則或訓練。
整體事件的行為標籤另計，不冒充逐軌跡評估。統計單位為回報者投票，不是獨立事件或全畫面準確率。

唯讀評估命令（不遷移資料庫、不輸出姓名、事件 ID、來源、Chat ID）：

```powershell
.\.venv\Scripts\python.exe tools\report_feedback_learning.py --database <現有SQLite路徑>
```

## 驗收界線

- 單元測試涵蓋採用／撤回、衝突、重複、過期、損壞特徵、時間／框與軌跡一致性。
- 真實 DINOv2 測試用公開貓素材與同一已載入 embedder 驗證建立 384 維回饋特徵、讀取合併。
- 這不是家庭貓甲／貓乙 準確率、真實 Telegram 點擊後正式 Host 學習或 MX250 負載驗收。
- 需用未參與學習的家庭片段另行評估，避免用訓練樣本自我驗證。

### 本輪驗證結果

- 完整回歸：428 tests passed（127.341 秒）；其後新增 3 項檢查，學習局部測試共 11 項全通過。
- 真實 DINOv2：公開貓圖片 → 同模型特徵 → 獨立回饋檔 → 既有分類器讀取通過；不是 Mock embedding。
- Ruff、compileall 通過。首次回歸失敗已修正：摘要 fixture 未初始化新 policy；學習工作與 pending 身分工作爭用佇列。
- 本輪沒有向真實 Telegram 發送，沒有重啟 Host／遷移正式資料庫，也沒有建立新版發布包。
- 真實 Telegram 回報 → 正式 Host 特徵擴充、家庭準確率與 MX250 負載仍為 `not_checked`。
