# 雲端拼貼與 Telegram 說明修正

## 2026-11-04 需求與行為

- 拼貼仍要求每條事件軌跡收齊設定數量的獨立、可解碼裁切，不補重複圖、不靜默略過其中一隻貓。
- 依使用者要求，低優先背景收集上限為 **3 秒**，觀察點只容許事件前 4 秒至事件後 3 秒；不延長原始錄影、不改雲端 API 的回覆逾時。
- 3 秒內收不齊就略過雲端，本機影片與 Telegram 通知繼續；低 FPS 時仍可能不足，不能保證所有事件外送。
- 保留既有隱私排除、軌跡工作階段、視角 epoch 與場景對位安全檢查。手動重分析仍只使用既有已保存歷史拼貼，不混入現在視角。

## 已修正的根本缺口

1. 原本收集只等待兩秒，但同時要求四張獨立影格，低 FPS 下新軌跡容易來不及收齊；現在使用有界三秒視窗，沒有降低圖片數量。
2. 超出觀察視窗的舊影格曾參與 epoch 判定，可能讓可用拼貼被舊工作階段污染；現在只判定有效視窗內的影格。
3. 拼貼答案正規化沒有保留可選 caption；背景 worker 又重建結果漏掉 caption／身分候選；工作帳本還原也漏欄位。現已逐層保留安全結構欄位，不保存供應商原始回應。
4. 送出前／送出後的本機身分更新可能覆蓋已完成的雲端說明；現依各訊息所屬事件合併既有雲端結果，不混用其他事件的雲端內容。

## 可辨識的略過原因

事件結果新增白名單 `evidence_reason` 與繁體中文 `evidence_message`，工作帳本保存同一終止原因；既有 `insufficient_evidence` 狀態相容不變，不需要 SQLite schema migration。

- 圖片：有效張數不足、指定軌跡無裁切、內容重複、間隔太短、無法解碼／尺寸不符、超出事件視窗、容量超限。
- 軌跡：圖片與事件軌跡不符、追蹤工作階段改變。
- 視角：鏡頭 epoch 改變、場景未對齊、視角狀態讀取失敗。
- 安全及生命週期：隱私範圍無法確認、影格收集停止、準備流程尚未就緒。

事件回報歷史以純文字呈現具體原因；日誌只輸出固定中文分類，不輸出來源網址、圖片、憑證或供應商錯誤原文。舊紀錄沒有細分欄位，不能憑新程式替歷史事件捏造原因。

## 驗證界線

- 回歸台帳：`CLOUD-STORYBOARD-COLLECTION-REASONS`、`CLOUD-CAPTION-PRESERVATION`。
- 三秒版本固定來源完整測試 1051 項、故障回歸 149 項通過，零略過；lint、Python 編譯與事件歷史 JavaScript 語法檢查通過。來源 SHA-256：`d00659c4dc9dfe7a2530a2d5fbf81fbc8123b2dae856cccad5356da7cf320238`。
- 隔離端到端：真實歷史攝影機影格重播、真實雲端 API、Telegram 影片及 editMessageCaption 回傳的實際 caption／video 欄位核對。
- 三秒限制另以同批真實影格重播，沿用先前雲端結果更新同一批測試影片，不額外外送圖片或重發影片。
- 上述不是正式 Host 部署、當前即時鏡頭連續監測或手機／手錶 UI 驗收；測試明確標示歷史片段。私有實機紀錄只放本機 reports 與測試主機，不上傳 GitHub。
- 正式程式未被覆寫或重啟；仍需依發布流程建置候選包、由使用者安裝後確認正式接線。不能把隔離成功當作已套用正式版。
