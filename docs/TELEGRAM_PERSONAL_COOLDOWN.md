# Telegram 個人貓咪通知間隔

- `/cd 15`：該已授權私人對話每 15 分鐘最多收到一輪自動貓咪通知。
- `/cd`：查看自己的間隔與剩餘冷卻秒數。
- `/cd 0`：取消額外個人間隔；仍遵守系統事件冷卻。
- 接受 0～10080 分鐘整數；不得替其他收件者設定。立即生效，不需重啟。

一般 `cat_detected` 影片／截圖與 V0.2 逐軌跡摘要共用同一個原子傳送額度；
不影響本機事件、錄影、身分分析、其他收件者或手動指令回覆。
個人間隔大於零且摘要超過圖片 Caption 上限時，只發一則完整文字附回饋按鈕，避免兩則提醒。
既有未設定使用者預設為 0，保持舊行為；全域事件建立冷卻可能讓通知更少，並不保證定時發送。

使用既有 `telegram-cat-notifications.json`，只保存收件者雜湊、個人偏好與最後傳送嘗試時間，
不保存 Token 或原始 Chat ID。讀取 v1／v2；下一次寫入為 v2。完整資料備份沿用此檔案。
兩條背景通知管線必須共用同一個 Preferences 實例（正式 Host 已如此接線）。
在網路傳送前持久化額度；錯誤／逾時也消耗間隔，以免未知送達結果造成通知轟炸。
同一次通知保留原本有限網路重試；Telegram API 沒有冪等鍵，因此不宣稱逾時重試能保證伺服器恰好一次。
設定寫入失敗時不發送；損毀檔案仍採 fail-closed。

驗收：每人隔離、15 分鐘邊界、重啟保留、並行競爭、舊格式遷移、私人對話授權、
一般事件與逐軌跡共用額度、超長摘要單則傳送，以及既有靜音／回饋／事件流程回歸。
真實 Telegram `/cd` 驗收需先由使用者升級執行中的 Host，程式碼或單元測試不代表已部署。
