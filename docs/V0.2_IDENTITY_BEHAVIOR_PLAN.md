- 目前是矩形數值輸入，尚無拖曳繪製／即時疊圖；瀏覽器互動與家庭座標準確性驗收仍待進行。

## 1. 目標與邊界

V0.2 在不重寫 V0.1 媒體、YOLO 與 Telegram 管線的前提下，新增可測試的多貓追蹤、
可配置寵物登錄、身分判斷、規則式基礎行為、SQLite 事件保存與疑似乾嘔候選流程。

本版不宣稱已完成家貓專用行為或嘔吐模型，也不加入 GUI、ONVIF/PTZ、Frigate、NAS 或
第二條攝影機連線。`track_id` 只代表短期追蹤，不是永久寵物身分。

## 2. 資料流

```text
單一 MediaSource / FramePacket
  → YOLO cat 偵測
  → BoT-SORT（persist + with_reid，短期 track_id）
  → TrackHistory / motion features
  → Zone + RuleBehaviorClassifier + hysteresis
  → BehaviorEvent / candidate event（pet_id 可先為 null）
  → SQLite 批次或狀態變更寫入
  → 現有 AnalysisPipeline／Telegram（只有明確啟用才外傳）
  → 背景 PetRegistry + identity backend（DINOv2／色彩／unknown）
  → 補寫同一 event_id 與統計
```

音訊候選只接受同一 MediaIngest 已產生的同步音訊觀測；音訊模組不得自行開啟 RTSP。
目前沒有經家中資料訓練的乾嘔權重，因此輸出只能是 `疑似乾嘔`／`疑似嘔吐事件`。

## 3. 模型與授權

- 偵測沿用已驗證的 `models/yolo11n.pt`，COCO `cat` class id 15。
- 身分特徵後端預設契約為官方 `facebookresearch/dinov2` 的 DINOv2 ViT-S/14。
- 固定 checkpoint URL：
  `https://dl.fbaipublicfiles.com/dinov2/dinov2_vits14/dinov2_vits14_pretrain.pth`。
- DINOv2 官方程式與模型權重採 Apache License 2.0；來源、版本、大小、SHA-256 與
  授權寫入 `models/identity/dinov2_vits14/model_manifest.json`。
- `tools/fetch_identity_model.py` 只允許上述官方 URL；缺少權重時開發／建置階段取得，
  執行時不接受不明 URL。無法載入 DINOv2 時，測試與乾跑可使用 MockEmbedding，正式
  身分結果安全回傳 `unknown`。
- PetFace、姿態模型、客製行為權重與 YAMNet 不在本版預設依賴。

## 4. MX250 效能策略

- 影像分析仍最高 5 FPS、640 像素級、batch 1、單一視覺模型。
- BoT-SORT 每個分析影格更新；DINOv2 只在新 track、遮擋後、低信心或低頻驗證時執行。
- 行為特徵最多每秒更新一次；SQLite 不逐影格寫入。
- DINOv2 支援 CUDA；無 CUDA 使用 CPU，並回報實際後端與延遲。
- 時序 R3D-18 只提供可替換訓練／推論框架，未取得通過驗證的客製權重時停用，規則
  後端仍是預設。

## 5. 主要資料契約

- `PetProfile`：UUID、顯示名稱、毛色／花紋描述、參考影像、建立時間、模型版本、啟用狀態。
- `IdentityPrediction`：預測 pet id／名稱、第一／第二相似度、margin、unknown probability、
  模型版本與是否穩定。
- `TrackObservation`：track id、bbox、時間、偵測信心、速度、加速度與來源。
- `BehaviorObservation`／`BehaviorEvent`：pet id、track id、主要行為、動作狀態、event tags、
  開始／結束、原始／平滑信心、依據、模型／規則版本、camera preset、人工確認。
- Zone 座標使用 normalized bbox 或 polygon，禁止寫死房間像素座標。

## 6. 行為初版規則

`RuleBehaviorClassifier` 是獨立可替換後端，集中設定最短持續、merge gap、速度、區域
重疊、信心與 hysteresis。進食／飲水支援短暫離開合併；睡眠需要長時間低動作；休息是
尚未達睡眠門檻的低動作；玩耍至少需要方向／加速度／互動／跳躍等多項證據。`running`
不能單獨轉成 `playing`。理毛與貓砂暫時保留候選／unknown，不假裝已準確辨識。

## 7. 測試與驗收

- 兩個任意寵物名稱可登錄，原始碼與測試不得寫死特定家庭寵物名稱。
- Mock embedding 可驗證已知身分、unknown、第二名 margin、時間投票與單一錯誤影格不換身分。
- Synthetic tracks 可驗證遮擋 reset、速度、running 不等於 playing、zone eating/drinking、
  meal merge、out_of_view 不算 sleeping。
- SQLite 可驗證 schema、事件寫入、人工確認與統計查詢；不逐影格寫入。
- 低 audio／低 visual 分數不能直接產生確定嘔吐；Telegram 未啟用不傳送。
- V0.1 全部既有測試必須維持通過，另執行 Ruff、compileall、模型／CPU fallback 與本地
  影片 dry-run。

## 8. 後續限制

實際 DINOv2 身分準確度、BoT-SORT ID switch、MX250 延遲、行為門檻與乾嘔候選召回率，
都必須以使用者後續提供的多角度寵物影像、遮擋案例、飯碗／飲水／貓床區域及人工 Telegram
標註資料校正；V0.2 不把初始分數當成醫療或個體辨識保證。

## 9. V0.2B 延伸規則

V0.2B 不改變上述模型與行為列舉，但將執行順序固定為「行為先、身分後」。行為事件
可以使用 `pet_id = null` 先建立；`identity_status`、`identity_confidence`、
`identity_resolved_at` 與 `identity_model_version` 由背景身分解析補寫。更新保留同一
`event_id`，並透過 `identity_corrections` 保留原始 unknown 與修正紀錄。

所有 DINOv2 工作經 `GPUInferenceScheduler` 的 LOW 佇列去重與限長；行為／異常的 HIGH／
CRITICAL 工作優先。身分失敗、逾時、crop 品質不足或 GPU 降級時回傳 unknown，不得丟棄
已建立的行為事件。

### 延後身分與人工確認保護

背景身分結果可依本次 session 的 track_id 回填 unknown 媒體事件，保留
identity_corrections 稽核及既有 telegram_receipts，不觸發重送。若身分在非同步
媒體 INSERT 之前已解析，建立事件時會讀取對應 track 已知身分。已知媒體身分
不自動改寫；同 track 存在人工鎖定行為時停止自動媒體補寫。
behavior_events 改用 UPSERT，避免 REPLACE 刪除 event_labels，並禁止 flush
覆蓋 human_review=1 的資料。244 項測試、Ruff、compileall 通過；仍需實際登錄
寵物後的背景辨識驗收。
