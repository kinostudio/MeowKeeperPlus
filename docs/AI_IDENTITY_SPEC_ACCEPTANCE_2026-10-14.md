## 已接線

- 重用 YOLO／追蹤／V0.2／SQLite／既有 Web 與 Telegram 回報，不新增攝影機連線。
- DINOv2 使用固定官方模型、共用 CPU 實例；身分低優先工作有界，模型不可用保存 unknown。
- 每隻寵物固定 top-K，比較有限且版本相容的特徵，輸出前三候選、相似參考照及未校準分數。

- 原始 AI 證據使用 `identity_inference_history`；人工回報使用既有 append-only history，不覆寫原推論。SQLite schema 16，migration 可重跑。
- media event→track 明確綁定；本機逐貓裁切與 Telegram 啟用無關。只保存有界、尺寸合格、不重疊且位於事件時段的裁切。
- Telegram 第一輪動態個體／其他貓／不是貓，第二輪行為與此筆學習同意／撤回。
- Dashboard 首頁摘要、事件證據、寵物特徵版本、单張比對、逐軌跡人工修正及學習同意共用既有服務。
- 受保護 JPEG／照片／影片沿用 Session；修改需 CSRF，修訂使用 revision；私有照片不送外部服務。
- 只有人工一致確認、明確同意、品質／版本／去重通過才擴充特徵庫。不是重訓 YOLO。

## 使用流程與資料

登錄寵物並建特徵 → 啟用 V0.2 → 查看 AI 候選 → 對指定軌跡修正 → 可選同意使用裁切 → 背景品質檢查 → 特徵版本更新。

SQLite 保存 AI 證據、人工歷史與裁切；寵物資料目錄保存 profile、原始 embeddings 與獨立 feedback_embeddings。可攜包與安裝版資料根不同，需使用既有完整資料備份／還原，不能假設自動合併別的套件資料。

本輪未修改 Xiaomi、go2rtc、RTSP、PTZ、launcher 或正式安裝。後续發布仍由使用者自行執行安裝代碼。
