# AI 看圖比對身分與 Telegram 逐軌跡回饋

本輪為來源程式實作，未建置新版、未安裝或重啟正式 Host。

## AI 自己指認

在「寵物檔案 → AI 看圖辨認是哪隻貓」上傳單隻貓的 JPG 裁切，AI 用 DINOv2、參考／回饋特徵與毛色融合進行身分比對。回傳候選姓名、融合相似度、第一／第二候選差距，並列出前三個近似參考照片。未知保留「尚未確認」，不要求使用者先指定照片是哪隻貓。

- 上傳圖不保存、不加入特徵、不寫入資料庫、不改訓練權重。
- 單張功能假設輸入是單隻貓裁切，不是 cat/person 偵測器；人像或多貓照片不能用它證明貓咪存在或數量。
- 同時只處理一張，工作在背景 threadpool 而非 ASGI event loop；模型首次使用才載入並重用，使用 CPU 避免搶佔主要偵測 GPU。仍有短暫 CPU／RAM 成本，不承諾零負載。
- 相似度不是準確率。候選參考照的分數是視覺 cosine，相片候選列表不含回饋裁切；融合候選結果包含合格回饋特徵及毛色，因此排序可以不同。
- 公開素材「同照比對」只驗證模型與 API 接線，不是兩隻家庭貓的準確率驗收。

已建立的特徵直接用於比對；參考照片新增／替換後需建立特徵。自動監控身分判斷另需啟用 V0.2，基本找貓只判斷有無貓。特徵库擴充不是重新訓練 YOLO；本輪未新增會修改模型權重的「重訓」按鈕。

## Telegram 第一輪

逐軌跡第一輪只有已登錄的動態貓名、其他貓、不是貓。選貓名／其他貓會在同一資料庫交易確認 cat presence 與身分，保存不可覆寫的單次人工操作歷史，再送出第二輪行為／動作選單。不是貓會撤除當前身分／行為標籤但保留歷史。舊訊息的 cat confirmation callback 仍可解析，避免已送訊息突然失效。

此為人工校正 AI 候選，不冒充 AI 結論；命名貓咪、其他貓與 unknown 的學習用途不同。「其他貓」不會學成任何已登錄個體。
