# CPU溫度顯示與參考數值（觀測設計，非新增控制門檻）

日期：2026-10-17。承接[真實隔離測溫](CPU_TEMPERATURE_REAL_TRIAL_2026-10-17.md)。這份文件定義下一階段觀測方向，不表示持續Dashboard監測已實裝；未新增特權服務、UAC或Host變更。

## 優先監控什麼

1. **CPU Package／可信Die**作為CPU主要指標，Core Max作為輔助。Package不可用但有單核心時明示來源，不冒充Package。
2. **GPU溫度保留既有路徑**；若AI使用外顯，CPU與GPU應分開顯示，同時觀察，不能只看其中一個。
3. **主機板溫度作為進階輔助**：需辨明System／Board／PCH／VRM，沒有明確部位不顯示單一「整台主機板溫度」，也不套用CPU門檻。現階段不為這項輔助資訊擴大硬體存取權限或採樣範圍。

理由：CPU直接承擔影音解碼、資料傳輸、事件處理及部分AI工作；Package較直接反映CPU熱狀態。板上溫度可補充機殼／供電／晶片組環境，但不是CPU內部溫度的替代值。

## 這台i7-10875H的參考數字

官方Tjunction為**100°C**，不是建議長期維持的目標，也不代表所有BIOS的節流點恰好100°C。

以下為本產品對這台已確認CPU的**觀察分級建議**，不是Intel官方的正常／異常分級，不外推到未知CPU：

| CPU Package | 介面建議說明 |
| --- | --- |
| 低於70°C | 相對較低，仍應結合負載與環境看待 |
| 70～未滿85°C | 溫度上升；觀察長期平均與風扇／負載 |
| 85～未滿95°C | 偏高，重點觀察是否持續，而非單次跳值 |
| 95～未滿100°C | 接近這顆CPU規格上限，檢查是否伴隨降頻／延遲 |
| 100°C以上 | 達到或超過其標示Tjunction；優先核對持續時間、感測來源及系統熱保護狀態 |

隔離試驗當時六筆86～91°C、平均88.83°C，落在建議「偏高」區。只有約10秒，且沒有同步長期整機負載，不能據此判定散熱故障、主機板過熱或主因是MeowKeeper+；也不是目前即時溫度。

Intel明確表示不提供適用所有CPU的典型操作溫度區間，重負載時接近上限不必然代表故障。低負載卻長期高溫，比短暫升頻尖峰更值得查原因。

## 下一階段應呈現的資料

- CPU Package：攝氏溫度、CPU型號、感測名稱／來源、最近量測時間與權限／過期狀態。
- 目前值與CPU使用率並列；近一小時平均、採樣峰值、有效採樣數、85°C與95°C以上持續時間，避免只有一個顏色或孤立數字。
- 預計5秒採樣、超過15秒不再顯示成即時；圖表的60秒儲存點與5秒即時值分開標示，不能拿歷史採樣峰值冒充逐瞬間絕對峰值。
- 硬體規格上限只使用已核對來源，記錄適用型號與來源；無可信上限時顯示未確認，不永久寫死100°C到所有電腦。
- 主機板資訊另列實際部位與獨立規格；缺資料就不顯示假值。

## 與既有AI保護的界線

目前AdaptiveSettings已有CPU警告85°C／危急95°C與持續時間策略；這些是可調軟體保守預設，不是硬體官方安全保證。本輪僅提出觀測參考，**未修改門檻，未把一次快照餵進即時控制**。

新LHM持續來源已在repository接入Telemetry快取與趨勢UI，尚未部署正式版；見[接線報告](CPU_TEMPERATURE_CONTINUOUS_INTEGRATION_2026-10-17.md)。一般權限已隔離驗證正確顯示permission_required；SYSTEM模式可在既有權限內另驗。永久特權bridge、服務或ACL變更仍需獨立安全審查，不因這份觀測設計擴大權限。

## 官方參考

- [i7-10875H規格](https://www.intel.com/content/www/us/en/products/sku/202329/intel-core-i710875h-processor-16m-cache-up-to-5-10-ghz/specifications.html)：Tjunction100°C。
