# Dashboard 品質標準與驗收

## 設計目標

以 Awwwards、Webby Awards、FWA 的設計完成度為參考，面向不熟悉串流與 AI 的寵物飼主。獎項是外部評審結果，不能以自評宣稱達到得獎水準。每輪應記錄實際檢查、修正及尚未通過項目。

方向為「安靜、可信賴的居家守護」：米白、卡其與低彩度大地色系、本機字型、留白及一致的按鈕層級。Dashboard 與 Windows Tray 圖示共用此視覺語言，狀態差異仍須可辨識。不要為裝飾加入持續動畫、額外攝影機連線或第三方追蹤資源。

參考：[Webby 評審標準](https://www.webbyawards.com/judging-criteria/)、[Awwwards 行動體驗指南](https://www.awwwards.com/mobile-excellence-guidelines.pdf)、[FWA](https://thefwa.com/)。目前未取得 FWA 明確的逐項評分規則，不臆造分數。

## 必須通過的使用體驗

- 總覽先呈現是否監控、是否有畫面、通知是否啟用；程序 running 不可直接當成監控成功。
- 已設定通知與真實發送成功必須區分；缺資料不顯示 0 或成功。
- 導覽、當前頁面與設定／維護分組在所有子頁一致。手機可收合導覽且支援鍵盤開啟與 Escape 返回。
- 使用者須能區分保存設定、套用設定及重啟服務的影響。
- 每個難懂設定旁說明用途、調整影響、適合何時調整；保留單位、有效範圍與實驗性限制。
- 說明使用可見文字及 aria-describedby；不可只放在滑鼠懸停才出現的 title。
- 技術診斷採漸進揭露；先提供白話摘要和下一步，再提供原始狀態碼。
- 載入、空白、離線、未登入、停用與失敗狀態有明確文字，過期資料不得仍看似即時成功。
- 使用本機字型及靜態資源；無額外 UI 輪詢、無外部 CDN／分析器，尊重 reduced-motion。
- 正文對比目標 WCAG AA 4.5:1；可點擊主要控制至少 44px 高，鍵盤焦點清楚。
- 桌面預覽 HUD 資訊與操作群組只在滑鼠移入或鍵盤聚焦時顯示；移開且焦點離開後保留2秒再淡出。觸控裝置保留可見操作，辨識框與短暫操作結果提示獨立顯示。
- 360／390／768／1440px 檢查：沒有水平捲動、文字截斷、無法觸及的操作；關閉 JS 仍能讀導覽與欄位說明。

## Telegram 按鈕色彩

Telegram Bot 按鈕沿用同一套語意層級，但 Telegram 只提供內建的 `primary`（藍）、`success`（綠）與 `danger`（紅）；沒有可指定品牌橘或琥珀色的自訂色碼。主要導覽／操作使用藍色，明確成功或肯定回覆使用綠色，拒絕通知、非貓回報與重新啟動等具風險操作使用紅色；一般身分不確定、行為選擇、返回及取消等中性選項保留 Telegram 預設樣式。狀態文字仍須包含文字或圖示，不可只靠顏色傳達。

## 檢查循環

1. 檢查真實頁面與現有資料契約，保留 DOM ID、事件處理與驗證。
2. 修改共享樣式／版型／說明，不同頁面不另造不一致的設計。
3. 執行 template／相關 Web 測試；在隔離的示例頁面檢查視覺及錯誤狀態。
4. 以實際瀏覽器檢查桌面和窄版；發現溢出、對比不足或操作不清楚就修正，再驗證受影響範圍。
5. 區分 repository 預覽、已建置發布包及已安裝版本。不用示例資料冒充真實監控驗收。

新增或變更難懂選項時，應同步提供說明；本文件為後續 UI 任務的路由文件。
