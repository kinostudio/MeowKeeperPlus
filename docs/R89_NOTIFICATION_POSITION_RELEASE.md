## 系統狀態改動是否完成

r88 已實作並打包電腦名稱、CPU/GPU 型號、RAM 容量、CPU/RAM/GPU 最近採樣／近一小時平均與採樣峰值、可取得的 CPU/GPU 溫度，以及整機磁碟讀寫量。r89 延續此功能。`tools/run_host.py` 已將 Telegram 狀態服務接到 Host 的 resource-history.db。

統計每 60 秒採樣，不足一小時顯示已涵蓋時間；感測器不可用顯示「未提供」，Windows CPU 溫度與 Intel GPU 用量未保證可取得。即時 CPU/RAM 與歷史最近採樣明確區分。這不是每個硬體都能回報所有感測器的承諾。

程式／包完成不代表使用者已安裝；本輪不自動升級或重啟正式 Host。真實 Telegram /status message_id 與使用者點擊仍需安裝後驗收。

## 通知流程

- cat_detected：即時偵測事件 MP4，維持既有冷卻、保存與背景送出，不等待身分。
- V0.2 finalized 行為：逐貓摘要。參與回饋者的一般短摘要改成同一則圖片＋編號摘要＋逐軌跡按鈕，SQLite receipt 綁該圖片 message_id，避免原先圖片和按鈕分散。
- caption 以 UTF-16 長度保守限制 1024；摘要過長才拆成圖片與完整文字，按鈕及 receipt 綁文字。圖片傳送失敗退回文字，不阻塞 ingest。
- 未參與回饋者只收到文字摘要，靜音／停用維持既有規則。
- 沒有把不同時間的 cat_detected MP4 與 finalized 行為硬合併，也沒有用當下圖片冒充整段行為；圖片註明觀測時間。兩分支的完全統一事件卡仍屬後續工作。

## 驗收界線

自動測試確認：双貓圖片／摘要／按鈕同則、圖片回執、未參與者純文字、長摘要退回、圖片失敗退回、位置座標邊界／錯誤與無有效讀回不顯示。

真實 Telegram 發送／callback、真實裝置讀回與圖點對照、手机視覺與硬體感測器完整性仍需部署後確認；本地測試不得當成家庭實拍準確率或 PTZ 真實位置驗收。
