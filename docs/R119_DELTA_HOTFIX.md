# r119 累積差量 hotfix

## 範圍

r119 以 r118 原始碼為底，累積 r116 之後的修正，直接提供 r116 → r119 的簽章檔案差量；不必先安裝 r117 或 r118。

- 保留前版三秒拼貼收集、略過原因分類與雲端影片說明保存修正。
- 保留安全更新交易、App／Data／工作定義回復、受保護暫存、獨占更新鎖與傳統 Windows 路徑長度防護。
- Telegram 指令與回饋接收遇到 400／409 時，不再永久退出；同一工作依 60／120／240／300 秒退避重查 webhook，保留接收游標。暫時網路及初始化錯誤使用既有 3～60 秒退避。
- 同時辨識 HTTP 狀態與 Telegram API 錯誤碼。401／403 或已設定 webhook 仍安全停用；不清除 webhook、不重設 Token、不建立第二個輪詢工作。
- 重試等待可由關閉程式中斷；恢復後記錄繁體中文提示。這不保證能排除另一台電腦上持續運作的重複 Bot 接收器。

## 更新契約

沿用 [差量更新契約](DELTA_HOTFIX.md)：固定官方 repository、Ed25519 簽章、精確基準與逐檔 SHA-256，基準不符即停止，不回退完整包。未變更的 runtime、CUDA、FFmpeg 及模型不重新下載。

適用基準為官方 r116 加簽章清單 `base_overrides` 中的已知公開 `state.py` 修正；不接受任意本機修改。換版會短暫中斷監控，仍需要本機重建及資料快照空間。安裝由使用者在本機執行，不由開發流程自動觸發 UAC 或升級。

## 驗收界線

發布前需完成固定來源完整測試、故障回歸、公開來源掃描、候選包完整性、簽章差量重建、原 r116 runtime 準備流程、包內 HTTP 啟動與公開資產下載再驗。最終數字與命令於發布後列於 [DELTA_HOTFIX.md](DELTA_HOTFIX.md)。

正式 Host 安裝、SYSTEM 更新工作、真實停止／啟動、正式資料失敗回復及斷電恢復仍須另行實機驗收；隔離通過不代表正式部署已完成。私人實機紀錄不包含在公開交付中。
